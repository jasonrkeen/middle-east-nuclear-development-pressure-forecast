# Security Policy

## Supported release

Security fixes are accepted for the latest published release.

## Reporting a software vulnerability

Use the repository's private GitHub security-advisory channel when available. Do not place exploit details, credentials, private data, or sensitive infrastructure information in a public issue.

Ordinary model questions, evidence disagreements, and reproducibility defects are not security vulnerabilities; use the corresponding issue form.

## Analytical safety boundary

The project excludes weapon design, engineering, targeting, procurement, and operational assistance. Public contributions should remain at the strategic, policy, safeguards, economic, or aggregate risk level.
